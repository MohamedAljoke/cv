# Resume & portfolio

Source of **https://mohamedaljoke.github.io/cv/**: a static site plus two ATS-friendly PDFs (English and Portuguese). All three come from the same JSON data, generated by a small Go program.

```
data/*.json  ──►  go run ./cmd/build  ──►  index.html, pt/index.html     (website)
                                      ├──►  resume/en.html, resume/pt.html (printable resume)
                                      ├──►  files/*.pdf                    (headless Chrome)
                                      ├──►  assets/og-*.png                (link preview images)
                                      ├──►  resume.json                    (JSON Resume export)
                                      └──►  ATS self-check on the PDFs
```

## Editing the content

Everything you'd change lives in `data/`. Each file declares its JSON Schema (`"$schema"`), so VS Code autocompletes fields and flags mistakes while you type. The build validates against the same schemas.

| File | What it holds |
|---|---|
| `profile.json` | name, headline, contact, links, summary, focus/core stack (web "at a glance" card), education, certifications, languages |
| `experience.json` | jobs, most recent first. Use `groups` (titled blocks of bullets) **or** a flat `bullets` list |
| `projects.json` | personal projects |
| `skills.json` | skill groups |
| `site.json` | languages, section order for the web and the PDF, PDF names and title, ATS keywords, every UI label |

**Text in two languages.** Any text field is either a plain string (same in both languages, e.g. `"Go"`) or `{ "en": "...", "pt": "..." }`. If one language is missing, the build fails and prints the exact path, e.g. `projects.json at /items/0/highlights/0: missing property 'pt'`.

**Visibility flags.** These work on jobs, groups, bullets, projects, skills, links, education and certifications:
- `"hidden": true`: removed everywhere (kept in the data for later)
- `"pdf": false`: website only. Use this to keep the PDF at 2 pages while the site shows everything.
- `"web": false`: PDF only

A bullet is either plain text or `{ "text": {...}, "pdf": false }`. Use `"note"` for private TODOs; notes are never rendered.

**Add a project:** append an object to `data/projects.json` (`id`, `name`, `summary`, optional `highlights`, `stack`, `repo`, `demo`), then run `make build`.

## Commands

```sh
make build     # site + PDFs + images + ATS check (needs Chrome/Chromium; set CHROME=/path if not on PATH)
make site      # HTML only, fast
make check     # ATS check on the committed PDFs
make test      # framework tests
make serve     # preview at http://localhost:8080
make match JD=job.txt [IN=pt]   # which terms from a job description your resume covers
```

Go 1.25+. No npm. CI (`.github/workflows/check.yml`) fails if the committed HTML is out of date with `data/`.

## What the ATS check enforces

It reads each PDF back as plain text, the way a parser does, and fails the build if:
- the PDF has more than `site.json → pdf.maxPages` pages
- a section heading isn't on its own line, or headings are out of order
- the name, email, a link (as text), a company or a job title is missing from the text
- a keyword from `site.json → ats.keywords` is missing
- the text is fragmented (many one-word lines; old Google Docs exports had this problem)

Design choices that keep parsers happy:
- one column
- standard headings ("Work Experience", "Experiência Profissional", …)
- no tables, icons or images in the PDF
- URLs printed as text
- static (non-variable) embedded fonts
- a tagged PDF with a real document title

## Design

- Tokens, type and accessibility rules come from the dyosmos design system: teal `#147d64` on slate, IBM Plex Sans with Barlow Semi Condensed, light and dark themes, 44px touch targets, visible focus rings, `prefers-reduced-motion`.
- Fonts are self-hosted (SIL OFL, see `assets/fonts/LICENSE-*`).
